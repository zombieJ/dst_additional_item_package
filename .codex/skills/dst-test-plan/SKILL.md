# DST 测试券自动化

使用这个 skill 把 git 变更转化为可由游戏内测试券一次触发并无人值守跑完的自动化回归。不要把控制台命令、逐项操作、等待条件或肉眼判定交给开发者。

## 核心约定

1. 开发者唯一需要执行的测试操作是使用一次 dev_mode 下自动发放的可重复测试券。
2. 使用测试券后，脚本自行建立前置状态、运行全部检查、恢复状态、清理实体、输出报告并自动暂停游戏。
3. 成功、断言失败、运行时异常、超时和前置条件不足都必须进入同一套收尾与报告路径，不向游戏回调抛出未捕获错误。
4. 不要求开发者打开控制台、粘贴命令、移动人物、观察计时、手工制造异常、复制日志或手工暂停。
5. Codex 负责执行离线回归；实机测试结束后也由 Codex 自行读取 DST 日志。开发者只需回到对话说明测试已结束。
6. 客户端 UI、动画、透明度和网络显示等行为必须通过客户端探针、网络状态或 dev-only 可观测量自动判定，不得改写成“请肉眼确认”。确实无法可靠自动判定时，报告自动化缺口，不得退化成手动测试步骤。
7. 测试券可随时再次使用；重复使用必须清理当前会话并从第一项重新开始，旧任务、旧报告批次和旧暂停回调不得影响新会话。

## 工作流程

### 1. 确定变更基准

1. 用户指定基准时使用该引用。
2. 否则运行 gh pr view --json baseRefName,headRefName,url；当前分支属于 PR 时使用 PR baseRefName。
3. 不是 PR 分支时回退到 master。
4. 远端基准需要更新时运行 git fetch origin <base>，优先与 origin/<base> 对比。
5. 检查 git --no-pager diff --stat <base>...HEAD、git --no-pager diff --name-status <base>...HEAD 和 git --no-pager log --oneline <base>..HEAD。
6. 同时检查未提交和未跟踪文件，避免遗漏正在开发但尚未提交的行为。

### 2. 把 diff 归纳为行为与风险

只读取理解行为所需的文件，把变更整理成少量端到端主题。每个主题明确可观察结果、前置场景、成功断言、失败与清理断言、旧行为回归，以及应在服务端、客户端还是两端检查。

不要逐文件复述 diff。一个端到端场景能覆盖时优先使用一个场景；只有 diff 暗示真实回归风险时才补充隔离用例。

### 3. 复用或补齐测试券入口

先搜索现有 dev 测试基础设施：

~~~powershell
rg -n "test_ticket|TestReport|DoStaticTaskInTime|SetServerPaused|dev_mode" modmain.lua scripts tests
rg --files scripts/dev scripts/prefabs tests
~~~

当前仓库的观光列车实现可作为标准参考：

1. scripts/prefabs/aip_pig_king_train_test_ticket.lua：dev-only、不可持久化、可重复使用的测试券入口。
2. scripts/dev/aip_pig_king_train_hook.lua：自动发券、服务端与发起客户端之间的报告和安全暂停 RPC。
3. scripts/dev/aip_pig_king_train_tests.lua：唯一会话、隔离场景、真实玩家流程、有界超时、统一 Finish、分批报告。
4. scripts/dev/aip_pig_king_train_scenarios.lua：不会伤害实际存档和玩家的隔离对象测试。
5. tests/pig_king_train_spec.lua：离线成功、失败、清理、报告分批和自动暂停回归。

已有测试券适合承载当前变更时直接扩展同一套测试，不要为每个小功能重复发放新券。只有测试域完全独立或共用入口会造成明显耦合时，才新增 dev-only 测试券。

### 4. 实现自动测试场景

1. 所有测试模块和 prefab 在 dev_mode 未启用时立即返回，不注册正式玩法入口。
2. 测试券由服务端登录钩子自动发放；背包已有时不重复发放；persists 必须为 false；使用后不消耗。
3. 一次只允许一个活动测试会话。重复使用时先让旧会话进入无报告、无暂停的重启清理路径，再建立新会话；不能拒绝、卡死或叠加实体、任务和监听。
4. 测试会话使用有限重试和总超时；禁止无界轮询、无限递归或等待玩家继续操作。
5. 同步断言使用 xpcall 或 pcall 收口；异步任务也通过统一包装捕获异常并调用 Finish。
6. 会话记录自己创建的任务、实体、事件监听、组件包装和临时状态；Finish 无论成功失败都取消任务、移除监听、清理实体并恢复玩家与世界原状态。
7. 能用独立对象验证的破坏性场景不要对真实玩家发送死亡、掉线、迁移或删组件事件。只有必须验证实际状态图、物理、HUD 或网络复制时才使用发券玩家，并确保流程自动完成。
8. 前置实体、物品、时间阶段、组件数值和世界事件由测试代码直接准备，不向开发者输出 c_give、c_spawn 或临时 Lua 命令。
9. 时间相关行为先使用 dst_reader 检查原版 clock、seasons 或目标组件，再由测试代码调用对应公开事件、LongUpdate 或有界静态任务。
10. 客户端行为通过专用 dev-only RPC 或网络变量回报结果。需要验证短暂视觉状态时，增加只在 dev_mode 生效的探针或计数器，并在检查后撤销；不要依赖截图或人工观察。
11. 多分片或专服场景若当前机器无法完整构造，让测试券输出明确的 SKIP 或 FAIL 及原因。不要把缺失覆盖伪装成通过，也不要改成开发者手测。

### 5. 统一报告与自动暂停

1. 每项检查输出独立的 PASS、FAIL 或 SKIP，失败包含场景名和单行错误详情。
2. 最终结果包含成功状态、通过与跳过数量、失败原因、关键状态或计数，以及清理后的剩余实体和任务数量。
3. 长错误先移除换行并限制单行长度，避免堆栈或实体字符串撑满控制台。
4. 报告使用 aipPrint 写入服务端日志，并同步给使用测试券的客户端；最近一份结构化报告保存在 TheWorld 的明确字段上。
5. 报告每批最多 3 行，批次之间使用约 0.15 秒的 DoStaticTaskInTime；必须等最后一批写出后再请求暂停。
6. 暂停由发券客户端的安全更新阶段或客户端 RPC 调用 SetServerPaused(true)，避免在服务端组件 OnUpdate 中途暂停。不是管理员或暂停请求失败时必须记录失败，但保留已完成报告。
7. 成功和失败都自动暂停，最终提示只要求开发者回到 Codex。
8. 每次 Start 递增会话代数；报告批次和暂停回调执行前核对代数。新测试启动后，旧代数的剩余报告立即停止且绝不暂停新测试。

### 6. Codex 自行验证

1. 按仓库 AGENTS.md 检查所有将执行脚本的编码和正文；修改后再次检查 UTF-8 与乱码。
2. 增加或更新离线回归，覆盖成功、断言失败、超时或异常清理、活动期间重复使用、报告期间重复使用，以及最后一批报告完成后才暂停。
3. 自行运行相关离线测试和 Lua 语法检查；不得让开发者代跑命令。
4. 不运行 DST 动画编译工具，不生成无关 tex、xml 或 zip 编译产物。
5. 保留用户已有工作区改动，只修改当前自动化所需文件。

离线检查通过后，实机阶段只说“使用一次测试券，自动暂停后回来告诉我”，不要附加其他操作。

### 7. 自动读取实机结果

开发者说明测试结束后，Codex 直接读取用户目录 Documents/Klei/DoNotStarveTogether 下最新相关日志：

1. 从测试开始标记读取到最终 TestReport 和 Server Paused。
2. 检查 LUA ERROR、stack traceback、提前中止、超时、未清理实体，及暂停是否发生在报告结束之前。
3. 成功则说明自动覆盖和关键指标；失败则根据日志自行修复、更新离线回归与测试券，再让开发者只使用一次测试券复测。
4. 不要求开发者复制日志、运行重放命令、输入控制台代码或手动恢复游戏。

## test.md 输出规范

每次使用本 skill 都将完整自动化方案同步写入仓库根目录 test.md，覆盖旧内容。test.md 包含：

1. 本轮 diff 对应的自动测试范围。
2. 唯一人工操作：使用一次测试券。
3. 测试券自动准备的前置状态和自动执行顺序。
4. 每个行为的程序化断言和回归断言。
5. 超时、异常、重试、清理、报告和自动暂停规则。
6. AIP 日志前缀、关键字段和成功或失败判定。
7. 测试结束后的协作方式：开发者只需回到 Codex，Codex 自行读日志。

test.md 不得包含 DST 控制台命令、命令行脚本、逐项人工操作、肉眼确认清单或要求开发者复制日志的说明。

## 无法自动化时

不要用手工测试填补自动化缺口。优先增加 dev-only 测试探针、场景 fixture、网络回报或可重复测试入口。如果补齐自动化会实质修改正式玩法、需要外部服务器权限或超出用户请求范围，则停止代码扩展，明确说明缺口和所需授权；在获得授权前不得把该项标为已通过。

文档截图、宣传画面和语雀配图准备不属于回归测试，应改用 yuque-doc-update，不要在本 skill 中恢复控制台截图或手工摆拍流程。

## 最终回复

最终回复只说明自动测试券新增或更新的覆盖、Codex 已执行的离线测试结果、test.md 位置。若仍需实机运行，只给出一个动作：使用测试券，自动暂停后回来告知完成。

不要再次粘贴整份手动测试计划，也不要要求开发者执行测试券之外的任何测试操作。
