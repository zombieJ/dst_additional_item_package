# Codex 记忆

## Lua 注释

- 修改 hook、组件劫持、事件监听、队列、延迟逻辑时，保留必要中文注释。
- Lua 注释参考项目现有写法，默认使用 `--` 单行注释。
- 不使用 `--[[ ... ]]` 长注释，除非原文件已经采用这种风格。
- 注释必须单独成行，不要在同一行的 `--` 后继续写 Lua 代码。
- 简化或重构代码时，不要删掉解释为什么这样做的注释。

## PR 描述风格

- PR 标题默认使用 Conventional Commit + 中文功能摘要，例如 `feat: 支持农作物品质系统`。
- PR 正文参考 #132 的发布说明风格：使用一整段中文描述，不写 `Summary` / `Test` 模板小节。
- 正文从主题更新开头，例如“农作物品质系统更新，...”，随后用中文逗号和分号串联玩家可感知的主要内容、行为变化和修复点。
- 描述重点面向玩家和维护者可读的行为变化，少写实现细节；只有直接影响玩家使用的技术点才点到为止。
- PR 正文不要写开发相关内容，包括 `dev_mode`、调试工具、测试辅助、本地 Codex/技能/记忆文件、内部脚本和实现过程，除非用户明确要求。
- PR 正文不要写玩家无感知的仓库整理内容，包括资源目录调整、导出文件移动、旧压缩包清理、格式化、内部文档或配置整理。
- PR 正文避免写偏内部规则的细节，例如合堆限制、拆分继承、具体掉落继承链路；这类内容改写成玩家体验层面的概括。
- 如果变更很多，按“新增内容 -> 行为调整 -> 玩家可见修复”的顺序组织在同一段里。
