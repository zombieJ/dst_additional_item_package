# 猪王观光列车景点与轨道生成优先级

## 文档目的

本文用于规划猪王列车生成临时观光轨道时应经过的 DST 经典景点，并给出开发优先级、运行时定位锚点和绕行要求。景点清单基于当前本机 DST 世界生成脚本整理，优先考虑玩家辨识度、视觉效果、实体坐标稳定性、默认世界可用性和自动铺轨安全性。

当前已接通“交付体验券 → 六站选点 → 外围观景点与绕障 → 分批铺轨 → 自动观光 → 回村清理”的完整流程。本版直接开放海上线路，与陆地线路共同接受总里程和实体预算限制。现有月亮轨道保持原有即时显示；观光使用独立临时端点、连接和矿车，复用月亮轨道贴图及客户端绘轨器，并只为临时观光轨道增加透明渐入。

### 当前实现与边界

- `scripts/aip_pig_king_train_route.lua`：P0、P1、P2 各两站，有限换选、最近邻排序与 2-opt；优先使用首选锚点，排除挨近的舞台与竖琴重复景点，以及已经被拿走的眼骨。
- `scripts/aip_pig_king_train_track.lua`：外围偏移、密集地标的有限扩圈、粗路线下界预检、地面优先与高架降级、有限 A* 绕行、40 单位分段、32 单位换高坡道、预算预检和流式创建；地面轨道避开全部实体，高架轨道只避开危险区和景点核心，原版实体不参与清理。
- `scripts/aip_pig_king_train_runtime.lua`：最多执行六轮“选六站 → 规划轨道”，根据失败景点或最远景点做排除后重选，创建独立运行并统一处理退款、结束和清理。
- `scripts/aip_pig_king_train_runtime.lua`：体验券交易、准备失败返券、运行 ID、多人隔离、超时与离线中止、景点播报及短暂纯视觉特效。
- `scripts/components/aipc_pig_king_train_passenger.lua`：把本次临时轨道的唯一下一端点提供给原 `aipc_orbit_driver`，由原组件通过运动向量完成移动、转向、上下坡和端点续行；本组件只观察到站、处理 X 键提前回村、V 键镜头与异常恢复，不逐帧改写人物坐标。普通玻璃矿车和观光车共用屏幕下方的鼠标调整第三视角、V 切换视野、X 下车提示；第三视角把整个屏幕映射为方向和俯仰，鼠标左右与画面转向保持一致，轨道角沿用原版平滑过渡，只在最终画面瞬时叠加鼠标偏角，纵向俯仰也立即响应，俯视视角不受影响。存档记录陆地总站坐标，不保存临时乘车状态。
- `scripts/prefabs/aip_pig_king_train_orbit.lua`：临时轨道和矿车始终不持久化，不进入普通矿车的节点搜索、安装或拆卸流程。
- 配置集中在 `scripts/configurations/aip_pig_king_train.lua`：考虑六段 270° 环绕后的总长上限为 3600、海上长度上限为 1800、全路线视觉片段估算上限为 6400、端点上限 256、同时最多 3 趟、单趟超时 600 秒；实际轨道按窗口流式展示，不会同时生成全部视觉片段。
- 当前所有景点均为减速掠过，不设置中途下车；起终点在猪王外围安全陆地，普通路线直接在地面出发，只有总站周围完全堵塞时才用短高架坡道，任何换高都保留水平距离，避免给原矿车驱动器生成纯垂直线段。发车前失败返还一张正式体验券；发车后主动退出或实际死亡等中止回村，不返券。普通受击、击退和临时状态覆盖会继续乘车；生命、饥饿、精神正常变化但最低保留 1 点，下车解除保底。
- 开发模式提供“测试实验券”，使用后执行隔离场景与真实六站乘车检查，无论成功失败都请求暂停，并用静态任务分批报告；使用方式见 [游戏内自动测试](pig-king-train-dev-tests.md)。
- 聚类景点、专属动物演出和 P3 洞穴跨分片专线仍属于后续扩展。Lua 回归测试位于 `tests/pig_king_train_spec.lua`；真实游戏的客户端同步、观感和海上性能仍需实机验证。

## 优先级定义

| 优先级 | 用途 | 选择标准 |
| --- | --- | --- |
| P0 | 首版地面观光环线 | 默认世界高概率或必定存在、锚点稳定、辨识度高、无需跨世界分片 |
| P1 | 地面扩充与海上长线 | 值得游览，但路线更长、跨海、具有环境危险或需要多锚点降级 |
| P2 | 彩蛋与可选固定内容 | 依赖世界设置、季节、世界进度或可移动实体，找不到时必须在本级换选 |
| P3 | 洞穴与远古专线 | 位于洞穴分片，必须另做跨分片乘车、轨道恢复和掉线保护 |

同一优先级内已经按推荐实现顺序排列。一次地面观光固定选择六站：P0、P1、P2 各两站。P3 位于洞穴分片，不参加地面猪王列车的六站抽取。

## 六站景点选择与路线图方案

### 文件与职责边界

- `scripts/aip_pig_king_train_route.lua`：维护可定位的景点候选、执行有限重试、生成六站访问顺序和闭环路线图数据。
- `scripts/aip_pig_king_train_runtime.lua`：在收到完整体验券后调用路线与铺轨模块，保存最终 `routeMap`，再创建本次观光运行。
- 景点模块只做选择和排线，不创建、移除或传送任何原版实体，也不直接生成轨道视觉片段。
- 当前路线坐标是景点锚点坐标。外围观景点、安全高度、折线中间点和碰撞绕行属于下一阶段铺轨器的职责。

### 固定选择配额

| 景点级别 | 每次数量 | 候选范围 | 失败处理 |
| --- | ---: | --- | --- |
| P0 | 2 | 地面经典固定地标 | 换一个尚未尝试的 P0 候选 |
| P1 | 2 | 地面扩充、月岛及海上长线 | 换一个尚未尝试的 P1 候选 |
| P2 | 2 | 世界彩蛋、升级地标和当前存在的裂隙 | 换一个尚未尝试的 P2 候选 |
| P3 | 0 | 洞穴、遗迹与远古区域 | 不进入地面六站池，后续单独做洞穴专线 |
| 合计 | 6 | 三个地面可用优先级 | 只有三组都凑满两个才返回路线图 |

这里的“各选两个”按 P0、P1、P2 三个当前分片可用级别计算。若把 P3 也加入，就会变成八站并涉及跨分片传送，与一次六站地面路线的目标冲突。

当前 Lua 模块先接入具有直接实体坐标的候选：

| 级别 | 当前代码候选 |
| --- | --- |
| P0 | 月台、龙蝇竞技场、绿洲、蜂王草甸、格罗姆雕像、舞台之手、绚丽之门 |
| P1 | 垃圾场、海象营地、大理石棋盘、试金石、麋鹿鹅巢、洞穴入口、月岛、隐士岛、猴岛、水中木、帝王蟹、深海漩涡 |
| P2 | 查理舞台、竖琴雕像花篱、泰拉瑞亚箱子、Balatro 机器、切斯特眼骨、天体传送门、月亮裂隙 |

墓园、牛群、鱼人村、蜘蛛森林、盐矿池等需要聚类识别的景点仍保留在完整规划池中，等独立定位器完成后再加入代码候选；不能为了扩大候选池而把任意一块同名资源误判成经典布景。

### 有限重试规则

1. 每次生成只遍历一遍当前世界实体，并按候选 prefab 建立临时索引，避免每次换选都重新扫描整个世界。
2. 每个优先级开始时复制一份候选池，随机抽取一个候选并立即从临时池移除，因此同一个景点配置不会在本轮反复命中。
3. 查找候选支持多个 prefab 降级锚点；同一配置存在多个实体时，使用离猪王最近的有效实体。
4. 实体已经移除、位于 Limbo、缺少坐标，或物品型锚点已经进入玩家和容器物品栏时，本次尝试判定失败并换选下一个候选。
5. 每个优先级最多尝试 12 次，同时不能超过该优先级实际候选数量。P0 当前最多 7 次，P1 最多 12 次，P2 最多 7 次，循环一定会结束。
6. 任一优先级最终不足两个时，整次选择返回 `not_enough_spots`，不生成残缺路线，也不从其他优先级借名额。
7. 六站齐全但出现 `no_viewpoint`、`no_safe_path`、`rough_route_too_long` 或 `track_budget_exceeded` 时，由运行层排除本轮故障景点；预算失败没有明确故障点时排除离猪王最远的景点。
8. 重试时保留上一轮其余五个有效景点，只补足被排除景点所在级别；若失败原因是总里程或轨道预算超限，补位优先选择该级别中离猪王最近的有效景点，使路线稳定向更短方案收敛，其他失败仍随机补位。
9. 完整路线最多规划六轮；成功即停止，候选不足、内部异常或达到第六轮时正常失败并返券，不使用无限循环。
7. 失败结果记录失败级别、已选数量、目标数量和各级尝试统计，供猪王提示、调试日志或体验券返还逻辑使用。

### 路线图生成

找到六个景点后按以下流程排线：

1. 从猪王坐标出发，每次选择离当前节点最近的未排序景点，生成最近邻初始路线。
2. 对初始路线执行最多四轮 2-opt 局部优化，通过反转局部访问顺序减少明显折返和交叉；该优化同样有固定终止上限。
3. 在路线末尾补回猪王村，形成“猪王村 → 六个景点 → 猪王村”的闭环。
4. 为每一段记录起点、终点和水平距离，并汇总估算总里程，供后续判断体验时长、海上超长路线和轨道实体预算。

`routeMap` 的主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `spotCount` | 固定为 6，只有完整选点成功才会生成 |
| `stops` | 已按实际访问顺序排列的六个景点 |
| `nodes` | 猪王起点、六个景点、猪王返程点，共八个节点 |
| `legs` | 相邻节点组成的七段粗路线及各段距离 |
| `totalDistance` | 七段水平距离之和，用于线路预算 |
| `selectedByPriority` | 按 P0、P1、P2 保留的原始抽取结果，便于验证每级正好两个 |
| `selectionStats` | 每个优先级的尝试次数、上限和成功数量 |
| `optimizePasses` | 实际执行的路线优化轮数，最大为 4 |

组件发布两个服务端事件：

- `aip_pig_king_train_route_ready`：携带 `doer` 和完整 `routeMap`，后续铺轨器应监听这个事件。
- `aip_pig_king_train_route_failed`：携带 `doer` 和结构化错误信息，后续应在这里提示玩家并决定是否返还体验券。

### 首版推荐候选池

猪王村固定作为起终点，P0 从以下候选中随机选择两个有效景点：

1. 月台森林；
2. 龙蝇熔岩竞技场；
3. 绿洲；
4. 蜂王草甸；
5. 格罗姆雕像；
6. 舞台之手玫瑰园；
7. 绚丽之门。

P0 的两个景点会与 P1、P2 各两个景点合并，再按世界实际坐标统一排序。列表排名表达实现价值，不代表列车固定访问顺序。

## 轨道生成约束

### 1. 景点定位

1. 每次乘车开始时重新扫描实体，不保存动态实体 GUID 作为永久配置。
2. 每个景点维护“首选 prefab + 降级 prefab 列表 + 可选拓扑标签”。
3. 多个同名实体使用聚类中心或选择距当前路线最近的一组，不直接取遍历结果第一项。
4. 找不到稳定锚点、锚点正在移除或位于 Limbo 时直接跳过，不为凑数量生成原版地标。
5. 玩家已经破坏或移动景点时尊重当前世界状态，不复原、不复制、不传送原实体。

### 2. 观景点偏移

- 轨道节点应位于景点外围，而不是压在锚点坐标上。
- 普通地标建议半径 10～16；Boss 场地建议半径 18～28。
- 试金石从 18 单位起搜索；一般观景点最多向外扩 24 单位，每 2 单位检查一圈，每圈固定 24 个方向，密集墓园也不会无限扩圈。
- 每个景点不再只有一个掠过点，而是在最小可用安全半径上生成约 270° 的观景圆弧；圆弧拆成 12 段。普通景点先按地面规则检查陆地和全部实体，只有完整圆弧被海岸或实体堵住时才抬升；危险景点直接使用高架圆弧并避开高架危险区。
- 每个半径同时尝试 24 个入弧方向和正反两个环绕方向，选择“上一站到入弧点 + 出弧点到下一站”预计距离最短的一组；本半径没有完整安全圆弧时才向外扩 2 单位，最多扩 24 单位，不会无限搜索。
- 地面轨道高度为 0；高架按景点危险范围使用 4～8 单位，接驳段以 32 单位短坡道换高，使原矿车在加速下坡时仍能跟上目标高度；站台、上车点和终点必须回到可落地高度。
- 停车点必须检查地面、碰撞体、火焰、海面和敌对实体；危险景点只允许减速掠过。
- 轨道不能移除树木、建筑、资源、海蚀柱或玩家实体来给自己让路。
- 普通接驳段先在陆地按全障碍规则直达或 A* 绕行；只有跨海或有限地面搜索确实失败时才降级为高架。高架段通常位于 6～8 单位，可以从普通树木和小建筑上方经过；火焰、敌对单位、Boss 危险半径和景点中心仍同时阻挡高架线路。

### 3. 轨道分段

普通月亮轨道的 `aipc_orbit_driver` 会在当前端点发现仍有唯一连接时继续开往下一端点。观光列车保留这套行为：线路提供器只在当前窗口的连接实体真实存在时返回下一端点，避免多人线路或永久轨道互相串线；移动、转向、上下坡和端点续行仍使用原驱动器。自动规划时普通接驳段的端点距离保持不超过 40，观景圆弧使用 12 段折线近似 270° 圆弧，兼顾视觉连接、曲线平滑和实体偏移。进入圆弧后原驱动器速度从 15 降为 7，离开圆弧自动恢复巡航速度。

长距离线路应插入中间端点形成折线，不要直接生成一根横跨地图的连接。海上长线还应限制视觉轨道总片段数，因为 `aipc_orbit_link` 当前约每 0.6 单位生成一个 `aip_glass_orbit` 视觉实体。

规划完成不等于一次性铺出整条轨道。完整路线只以坐标数据保存在运行记录中；发车时创建当前段及后续三段，共 5 个端点和 4 个连接，列车经过新端点后再创建一段。画面中额外保留身后一段用于视觉连续，因此正常情况下最多同时存在 6 个端点和 5 个连接。新出现的观光连接会在约 0.85 秒内从起点向终点透明渐入；此逻辑只包装观光专用连接，不修改玩家普通月亮轨道。更早的连接实体会立即移除，由 `aipc_orbit_link:OnRemoveEntity()` 清掉对应轨道贴图；远处路线尚未生成实体，所以交叉、返程和圆弧线路不会提前叠在同一个画面里。

### 4. 路线选择

当前流程：

1. 以猪王为始发点，按 P0、P1、P2 顺序分别执行不放回随机抽取；
2. 每级选满两个，共得到六个景点，遇到无效候选时在对应级别内有限换选；
3. 任一级别不足两个就终止整次生成，不输出部分路线；
4. 将六站合并，用最近邻生成初始顺序，再执行最多四轮 2-opt 优化；
5. 回到猪王坐标，输出八个节点、七条粗路线和总里程。
6. 铺轨前先根据所有观景点允许的最大偏移和六段 270° 圆弧的最低弦长计算粗路线距离下界；只有下界仍超过 3600 才直接换点，避免为确定不可能的长线扫描全世界障碍。
7. 对可恢复的规划失败最多重选六轮，日志记录 `plan-attempt`、`plan-rejected`、`excludeNext` 和 `plan-retry`。

已接入的铺轨流程：

1. 先把六个景点核心全部登记为高架禁入区，防止前一个景点的圆弧穿过后续景点；
2. 普通景点先有限搜索完整安全的地面 270° 观景圆弧，危险景点直接搜索高架圆弧；地面圆弧不可用时只把该圆弧降级为高架，不把轨道直接压到锚点中心；
3. 根据上一站出口和下一站锚点选择入弧位置及正反环绕方向，进入圆弧时播报景点并切换到观景速度；
4. 接驳线先检查陆地与全部障碍并尝试地面直达或有限 A*，跨海或地面无解时才按高架规则重新寻路；在相邻景点间插入水平距离不超过 40 的折线节点，并在换高边界生成 32 单位连续坡道；
5. 根据含圆弧的总里程限制海上线路和 `aip_glass_orbit` 视觉实体预算；
6. 发车时生成初始 5 个端点和 4 个连接；到达端点后将窗口向前移动一段，始终只展示身后 1 段、当前段和后续 3 段，新出现的观光轨道按行进方向透明渐入；
7. 线路提供器同时检查下一端点及对应连接仍然有效，只有“端点还有路”时才让原驱动器继续行驶；
8. 移除窗口后方的临时连接和孤立端点，连接组件同步清除客户端轨道贴图；
9. 创建前拒绝水平距离为零的相邻端点；人物运动向量无效或连续 5 秒没有位移时安全中止，避免永久卡车；
10. 乘车结束或异常中止后，恢复原驱动器速度，只清理本次临时轨道、矿车和演出实体。

### 5. 安全与世界状态

- 观光列车不得触发真实 Boss 战、召唤流程、世界进度或战利品掉落。
- 不得自动开凿洞穴、敲击蜂巢、激活月台、献祭、开宝箱或改变 NPC 任务。
- 玩家死亡、掉线、换分片和服务器关闭时都要有清理与回退路径；受击与击退不结束观光，应恢复驾驶状态并继续由原矿车物理驱动器行驶。
- 多名玩家同时乘车时，各路线应有独立运行 ID，清理时不能误删玩家永久铺设的月亮轨道。
- 临时轨道应显式标记为非持久化或保存所属运行 ID，避免服务器重启留下半条线路。

## 建议开发顺序

1. 已完成独立六站选点模块、有限重试、最近邻排序、有限轮次 2-opt 和路线成功/失败事件。
2. 已补充外围观景点、危险半径与不可中途下车属性，把锚点坐标转换为安全轨道坐标。
3. 已接入地面优先、危险圆弧与跨海/无地面通路高架降级、32 单位换高坡道、40 单位分段铺轨、有限绕行、线路总长与视觉轨道片段预算。
4. 已实现临时运行 ID、自动上车、终点下车、异常中止、发车前失败返券和完整清理。
5. 已通过 `aipPrint` 分层输出规划轮次、排除景点、候选现存数量、换选过程、六站坐标、访问顺序、粗路线安全下界、绕行结果、各项预算、运行 ID、到站事件、结束原因和清理结果；保持逐帧移动静默，避免日志刷屏。
6. 已把测试券的规划失败改为正常失败报告；找不到猪王、无法规划或缺少运行记录都会清理并暂停，不再通过断言制造 Lua ERROR。
7. 已接入减速、镜头、景点播报与纯视觉短暂特效，专属动物演出留待后续扩展。
8. 完成海上长线性能验证后，再单独设计洞穴专线与跨分片换乘。
