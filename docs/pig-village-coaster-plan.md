# 猪村委托与列车体验券计划

## 文档状态

- 当前分支：`codex/pig-village-coaster-challenge`
- 当前阶段：任务逻辑、正式素材、公共能力复用与开发模式测试配置已接入，等待游戏内验证
- 本次范围：猪村委托、随机奖励、体验券碎片、三个碎片合成正式体验券
- 本次不做：猪王兑换体验券、临时轨道、矿车体验和过山车沿途事件
- 资源约束：只提交处理后的 PNG 与 `exported` 动画源文件，不主动运行 DST 编译工具，不生成新的编译产物

## 目标

猪王村每天最多保有三个活动委托。委托属于猪窝并长期保存，但由该猪窝当前刷新的猪人展示和接收物资。玩家把指定基础物资直接交给猪人后推进任务；完成任务会获得一份随机奖励，并稳定获得一张列车体验券碎片。三个碎片自动合成一张正式体验券。

本次实现只保证玩家能够稳定获得正式体验券，不接入猪王过山车逻辑。

## 已确认规则

- 每个猪王村的目标任务数为 3 个。
- 系统每天只在新一天刷新一次，把活动任务补足到 3 个。
- 当天完成任务后不会立刻生成替补任务。
- 未完成的旧任务继续保留，并占用次日的三个任务名额。
- 任务记录保存在猪窝，而不是猪人；猪人死亡、回窝或重新刷新不会丢失任务。
- 任务物资直接交给对应猪人，不能交给猪窝或其他猪人。
- 需求只使用基础物资。
- 需求数量从 `2、4、6、8` 中随机选择，始终为偶数。
- 完成后随机获得金子或一颗宝石。
- 金子数量等于任务需求数量除以 2，即 1 至 4 个。
- 宝石奖励固定为 1 颗，珍贵宝石概率更低。
- 每个任务始终额外奖励 1 张列车体验券碎片。
- 玩家拥有至少 3 张碎片时，自动消耗 3 张并生成 1 张正式体验券。

## 本次实现阶段

### 阶段一：猪村与每日任务调度

1. 识别猪王所属的世界拓扑区域。
2. 找出同一拓扑区域内的有效猪窝；暂时没有居民的猪窝也能保存任务。
3. 首次加载时补足三个任务。
4. 每个新的一天检查一次，把活动任务补足到三个。
5. 当天完成后只减少活动任务数，不立即补位。

### 阶段二：猪窝任务记忆与猪人交付

1. 任务类型、需求数量和完成进度保存在猪窝组件中。
2. 猪人外出时通过原版 `homeseeker.home` 找到自己的猪窝。
3. 有任务的猪人展示任务提示，并临时接管其交易判断来接收指定物资。
4. 支持分批交付和整组交付；超过剩余需求的物资退回玩家。
5. 猪人死亡或被替换后，新居民继续继承猪窝里的任务。

### 阶段三：奖励与体验券合成

1. 按权重生成金子或宝石奖励。
2. 金子数量按需求数量除以 2 计算，宝石只生成一个。
3. 每次完成稳定发放一个体验券碎片。
4. 自动统计玩家物品栏里的碎片总数，每满三个合成一张正式体验券。
5. 本次只生成体验券，不处理向猪王兑换或启动列车。
6. 将正式体验券与碎片素材去除白底、裁切并规范化，分别生成 64×64 库存图和单帧地面动画源文件，再替换当前复用的莎草纸资源。

### 阶段四：验证

1. 验证首次生成、跨天补位和当天不补位。
2. 验证任务跟随猪窝跨越猪人死亡、回窝与重新刷新。
3. 验证数量始终是 2、4、6、8。
4. 验证交付、奖励权重、碎片累计和自动合成。
5. 验证保存、加载、回档、多人交付和物品栏已满。

## 详细设计

### 1. 组件职责

系统拆成两个服务端组件：

- `aipc_pig_village_quest_manager`：挂在猪王上，负责找到村内猪窝、统计活动任务数、每天补足三个任务。
- `aipc_pig_village_quest`：挂在猪窝上，保存任务类型、总需求、已交数量，并把任务能力同步给当前居民。

猪王不保存活动猪窝 GUID。读档后通过同一 topology ID 重新扫描带任务的猪窝，避免实体 GUID 变化导致任务失联。

### 2. 猪村识别

优先使用 `TheWorld.Map:GetTopologyIDAtPoint`。猪窝与猪王的 topology ID 相同才视为同一个猪王村。

候选猪窝必须满足：

- prefab 为 `pighouse`；
- 实体有效且没有烧毁或正在燃烧；
- 拥有原版 `spawner`；
- 不要求当前居民存活；空猪窝会先保存任务，等新猪人刷新后继承。

若特殊世界无法取得 topology ID，降级为猪王周围 60 单位的距离判断。

### 3. 每日补位规则

任务管理器监听世界的 `ms_cyclecomplete` 事件。

每次刷新流程：

1. 扫描村内所有仍有效的活动任务。
2. 计算 `缺口 = 3 - 活动任务数`。
3. 从没有任务的有效猪窝中随机选取缺口数量。
4. 为选中的猪窝生成新任务。
5. 如果有效猪窝不足，只生成能够承载的数量，下一天再尝试补足。

例子：

- 清晨有 3 个任务，当天完成 2 个，当天剩余时间只有 1 个任务。
- 第二天刷新时保留旧任务，并新增 2 个，恢复为 3 个。
- 如果一个任务一直没完成，它会持续占用一个任务名额。

首次加载系统时延迟 5 至 15 秒执行一次补位，避免必须等待下一天才能看到任务。

### 4. 基础物资池

首版物资池：

| 物资 | Prefab | 权重 |
| --- | --- | ---: |
| 草 | `cutgrass` | 3 |
| 树枝 | `twigs` | 3 |
| 木头 | `log` | 2 |
| 石头 | `rocks` | 2 |
| 燧石 | `flint` | 2 |
| 蜂刺 | `stinger` | 1 |
| 种子 | `seeds` | 3 |
| 花瓣 | `petals` | 3 |

每项任务独立从 `{ 2, 4, 6, 8 }` 中等概率抽取需求数量。物资和数量一旦生成便写入猪窝存档，读档不会重新随机。

同一天生成的三个任务尽量使用不同物资；候选类型不足或旧任务已经占用多种物资时允许重复，但同一猪窝不会同时存在多个任务。

### 5. 猪窝任务数据

猪窝任务组件保存：

| 字段 | 用途 |
| --- | --- |
| `task_prefab` | 要求物资的 prefab |
| `required_count` | 总需求，只能为 2、4、6、8 |
| `delivered_count` | 已交付数量 |
| `is_completing` | 防止重复完成的运行时锁，不写入存档 |

猪王任务管理器不需要保存冷却日期，因为刷新只发生在新一天；当天完成任务后不会主动调用补位。

### 6. 猪人与任务同步

原版猪房的 `spawner` 会在猪人外出时通过 `homeseeker.home` 关联住宅。猪人本身不保存任务，只在运行时读取猪窝组件。

- 猪人在外：显示任务标记，可以接收物资。
- 猪人回窝：任务继续保存在猪窝，但夜间不能交付。
- 猪人死亡：猪窝任务和进度保留。
- 新猪人刷新：新居民自动继承同一猪窝的任务提示和交付能力。

任务标记优先跟随猪人；居民不在场时，标记显示在猪窝上方，用于提示任务仍然存在。附近任务目标位于屏幕外时，复用原版问号方向引导帮助玩家找到可交互目标，目标回到屏幕内后自动隐藏引导。

### 7. 直接交付给猪人

猪人原本已经拥有 `trader` 组件。任务逻辑会保存原有交易回调，并在该猪人对应猪窝有任务时优先处理任务物资。

部分基础物资不带原版 `tradable` 组件。任务期间将猪人原版 `trader.acceptnontradable` 临时设为 `true`，复用组件自动维护的联网 `alltrader` 标签提供标准 `GIVE` 动作；服务端仍由任务组件校验实际物资，任务结束后恢复旧值。

玩家点击检查任务猪人时，任务需求由猪人自己的说话组件显示，不由玩家角色代为朗读；检查猪窝时仍显示猪窝保存的任务进度。

交付规则：

- 只有对应猪窝的当前居民能够接收任务物资。
- 任务期间，指定物资优先按任务交付处理。
- 支持一次交付整个堆叠。
- 实际消费数量不超过剩余需求。
- 超出的数量退回玩家；物品栏已满时落在玩家脚边。
- 任务期间猪人的交易临时切换为任务模式，错误物资会被拒绝且不消耗；任务完成后完整恢复原版喂食、雇佣和帽子交易逻辑。
- 完成处理先上锁，再清除任务交易状态，避免多人重复结算。

任务检查文本示例：

- `俺要 6 个木头！还差 4 个！`
- `木头收到啦！还差 2 个！`
- `够啦够啦！这个给你！`

猪窝检查文本示例：

- `这里的猪人正在收集木头：2 / 6。`

### 8. 奖励权重

每次完成任务只从下表抽取一项随机奖励：

| 奖励 | 概率 | 数量 |
| --- | ---: | ---: |
| 金子 `goldnugget` | 50% | `required_count / 2` |
| 红宝石 `redgem` | 15% | 1 |
| 蓝宝石 `bluegem` | 15% | 1 |
| 紫宝石 `purplegem` | 8% | 1 |
| 橙宝石 `orangegem` | 5% | 1 |
| 黄宝石 `yellowgem` | 5% | 1 |
| 绿宝石 `greengem` | 2% | 1 |

总概率为 100%。红、蓝宝石保持较常见；紫宝石居中；橙、黄宝石较少；绿宝石最低。

随机奖励发给完成最后一次有效交付的玩家。物品栏已满时，奖励落在玩家脚边。

### 9. 体验券碎片

每个完成任务的玩家始终额外获得一个 `aip_train_ticket_fragment`。

碎片规则：

- 可以堆叠；
- 进入玩家物品栏后延迟一帧检查该玩家拥有的碎片总数；
- 每拥有 3 个碎片，就消耗 3 个并生成 1 个 `aip_train_ticket`；
- 如果一次拥有 6 个碎片，则生成 2 张体验券；
- 合成后的体验券直接进入物品栏，放不下时落在玩家脚边；
- 正式体验券本次只作为可保存物品，不具备猪王兑换行为。

已有 `aip_train_ticket.lua` 骨架会在本次修正名称字符串、物品注册和交易属性，但不会调用 `aipc_pig_king_train:StartTrain`。

### 10. 存档与恢复

- 猪窝保存任务 prefab、总需求和已交数量。
- 猪王每天通过扫描恢复活动任务集合，不保存猪窝引用。
- 任务标记与猪人运行时回调不持久化，读档后重新绑定。
- 碎片和体验券使用普通物品存档。
- 读档后如果玩家已经持有三个以上旧碎片，会在碎片进入或玩家初始化检查时完成合成。

### 11. 异常处理

- 猪人死亡：保留猪窝任务，等待新居民。
- 猪人回窝：暂停交付，不取消任务。
- 猪窝烧毁或被砸毁：取消该任务；已投入物资不额外返还，避免通过破坏住宅反复取回物资。
- 当天任务完成：不调用补位，只等待下一次 `ms_cyclecomplete`。
- 多人同时交付：服务端顺序处理，只有一个玩家触发完成与奖励。
- 奖励接收者失效：奖励从猪人位置掉落。
- 村内不足三个有效猪窝：按实际数量生成，第二天继续尝试补足。
- 洞穴世界：不生成猪王任务管理器。

### 12. 现有能力复用

- 任务与奖励的权重抽取复用 `aipRandomLoot`，不在任务配置中维护第二套权重随机实现。
- 随机任务数量与候选猪窝复用 `aipRandomEnt`，候选移除复用 `aipTableRemove`，排除已占用物资时复用 `aipCloneTable`。
- 奖励、退还物资、体验券和任务标记的 prefab 创建复用 `aipSpawnPrefab`，继续使用 `aipFlingItem` 处理无法直接进入物品栏的掉落。
- 任务猪人的交易回调通过原版 `Trader:SetAcceptTest`、`SetOnAccept`、`SetOnRefuse` 和 `SetAcceptStacks` 接管，并完整保存及恢复旧值。
- 基础物资交付复用原版 `trader.acceptnontradable` 与其自动维护的联网 `alltrader` 标签，不再额外注入全局 `AddComponentAction`。
- 村内猪窝扫描继续复用已有 `aipFindEnts`；世界拓扑 ID 判断没有等价公共函数，保留任务管理器内的局部实现。

### 13. 开发模式测试配置

猪村委托统一读取模组已有的 `dev_mode == "enabled"` 配置，并在任务配置文件内集中覆盖测试参数：

| 参数 | 正式模式 | 开发模式 |
| --- | ---: | ---: |
| 首次补位延迟 | 5～15 秒 | 1 秒 |
| 次日补位延迟 | 5～30 秒 | 1 秒 |
| 单个任务需求 | 2、4、6、8 随机 | 固定 2 |
| 猪人运行时同步间隔 | 1 秒 | 0.25 秒 |

开发模式仍保持每天最多三个任务、当天完成后不立即补位、正式奖励权重和三个碎片合成一张体验券，确保测试捷径不会绕开本次功能的核心规则。关闭开发模式后必须完全恢复正式参数。
